# 選擇與後果：架構設計

> 狀態：提案（2026-10-15），等 Zhengxian 審閱。配合 [GDD.md](GDD.md)、[architecture.md](architecture.md)。
> 目的：遊戲裡每個選擇都可能在幾個月、幾年、甚至幾代之後引發後果。這份文件定義後果怎麼被記住、傳開、累積、觸發，以及怎麼追查「為什麼會這樣」。

## 1. 問題：現在的做法撐不住

SimCore 文字版目前用三種零散的東西記後果：

| 現在 | 例子 | 問題 |
|---|---|---|
| 旗標（flag） | `schooled`、`lord_favour`、`friend_12` | 只有「有或沒有」，不知道誰做的、何時、為什麼，也不會淡忘 |
| 好感修正值 | `quarrels -4（4 年）` | 每個事件自己加數字，彼此不知道對方；看不出好感是怎麼來的 |
| 冷卻時間 | 「三年內不再觸發」 | 只能防重複，不能表達「事情還沒完」 |

這些夠用來跑一百年的編年史，但撐不起「十年前拒婚，結果孫子那代兩家還在鬥」這種連鎖。所以要先換掉底層，再擴內容。

## 2. 一個例子：要能自然長出來的連鎖

> 1340 年，Atwood 家拒絕了 Miller 家的提親。
> → Miller 家記下「被拒婚之辱」，村裡人都知道（公開）。兩家開始有嫌隙。
> → 1349 年瘟疫後，Miller 繼承磨坊。Atwood 家來磨麥時，他故意抬價。
> → Atwood 的兒子半夜燒了磨坊的麥垛（秘密）。鄰居 Agnes 看見了，成為唯一的知情者。
> → Agnes 拿這件事勒索 Atwood 家；或者她跟丈夫說了，丈夫在酒館說溜嘴，消息傳開。
> → 消息傳到領主耳裡，莊園法庭開審。兩家的嫌隙升級成世仇。
> → 1372 年，兩家的孫輩相愛了。玩家要選：成全他們、化解世仇，還是讓仇延續下去。

這條鏈上沒有任何一步是寫死的劇本。每一步都是某個規則，看到前面留下的痕跡後才觸發。底下的架構就是為了讓這種事自然發生。

## 3. 七個構件

### 3.1 行為紀錄（Deed）：所有後果的源頭

每件有意義的事都寫成一筆紀錄，而不是設一個旗標：

```
Deed {
  id, 類型（refused_proposal、arson、helped_in_plague、slander …）,
  日期, 做的人, 對象, 其他相關的人,
  分量（1–100）,
  公開程度：public（全村都知道）| private（當事人知道）| secret（只有做的人知道）,
  起因：另一筆 Deed 或玩家指令的 id,
  標籤（violence、honour、money、church …）
}
```

旗標、冷卻、「有沒有做過」都改成查行為紀錄，例如：「三年內 Miller 家有沒有對我家做過帶 honour 標籤、分量大於 20 的事？」

### 3.2 記憶（Memory）：每個人怎麼看那件事

同一件事，對受害者、目擊者、獲益者的意義不同。每個知道這件事的人，都有一筆指向它的記憶：

```
Memory { deed, 身分（做的人 | 受害者 | 目擊者 | 聽說的）, 強度, 開始淡忘的速度 }
```

- **好感從記憶算出來。** 好感＝天生相性（特質、親屬）＋所有相關記憶的貢獻，貢獻依記憶的強度與淡忘程度計算。UI 能直接列出：「你對 Miller 的好感 −35：被拒婚之辱 −20、燒麥垛的傳聞 −25、一起熬過瘟疫 +10」。
- **記憶會傳給下一代（家族記憶）。** 家主死時，他的重要記憶（世仇、恩情、欠債）以較弱的強度傳給繼承人。這是「上一代影響這一代」的核心機制，不只傳財產，也傳恩怨。
- **記憶會淡忘。** 小事幾年就淡了；殺父之仇可能要三代。淡忘速度依 Deed 類型和個性（「記仇」特質會讓仇恨淡得更慢）。

### 3.3 知情（Knowledge）：秘密、傳聞、把柄

秘密的 Deed 有一份**知情者名單**。

- **傳播**：每個月，知情者和人來往時有機率說出去，機率取決於個性（健談、刻薄的人容易說）、與當事人的關係，以及事情多刺激。說出去的版本可能被誇大（分量變大），也可能記錯人。
- **把柄**：知道別人的秘密，就能發起「勒索」「揭發」計畫。
- **玩家視角**：玩家只看得到自己家族的人知道的事（已決定）。編年史和 UI 都經過這層過濾。
- **打聽（已決定）**：玩家可以主動打聽秘密，例如請人喝酒套話、問神父、收買僕人、偷聽。打聽到的東西**可能是錯的**。
- **知道的是「相信」，不是事實。** 所以知情要存成「信念」，不是直接指向真相：

```
Belief { 關於哪筆 Deed（或憑空捏造的說法）, 相信是誰做的（可能認錯人）, 可信度 0–100, 從誰那裡聽來, 何時 }
```

  **事實與信念分兩層（已決定，2026-10-15）**：Deed 是事實層，永遠記著真正是誰做的，系統的連鎖、因果、故事線、「真相大白」事件都依事實推進。Belief 是信念層，角色做決定和玩家看到的都是這一層。兩層的落差本身就是劇情來源：系統知道真兇是誰，所以能安排真兇露餡、良心不安自首，或讓被冤枉的一方記恨。

  錯誤的信念有三種來源：傳話時記錯人、被人故意栽贓（造謠計畫可以捏造 Deed）、打聽時被騙。玩家依信念行動，例如報復、告上法庭、退婚；如果信念是錯的，就會冤枉好人，而被冤枉的一方會留下真實的 Deed（「被誣告」），引發新的連鎖。可信度可以靠多方打聽、找證人來提高。

### 3.4 訊號（Signal）：讓後果能被「聽見」

每個狀態改變都發出一個有型別的訊號，例如 `deed.created`、`person.died`、`marriage.formed`、`secret.revealed`、`plan.exposed`、`land.transferred`。

- 事件除了定期抽選，也可以掛在訊號上：`"on": "deed.created", "when": {"deed_type": "refused_proposal", "victim": "me"}`。
- 訊號可以延遲：`"after_months": [6, 24]` 會排進一個依日期排序的佇列，到期才觸發。「一年後他還記得」就是這樣做的。
- 這讓內容之間不必互相知道。寫「勒索」的人，不需要知道「燒麥垛」是哪個事件產生的，只要聽 `deed.created` 裡帶 `secret` 和 `crime` 標籤的訊號即可。

### 3.5 故事線（Story Arc）：跨越多年、甚至多代的事

有些事不是一次性的，而是會發展的。故事線是一個長期存在的狀態機：

```
StoryArc {
  類型（feud 世仇、debt 欠債、courtship 戀情、affair 私情、inheritance_dispute 爭產、patronage 恩庇）,
  參與的「家族」（不只是個人）, 目前階段, 變數（例如仇恨程度）,
  開始日期, 起因 Deed
}
```

- 故事線會聽訊號來升級、降溫或結束。例如世仇：嫌隙 → 爭執 → 暴力 → 血仇；和解婚姻、教會調解、一方絕戶都能讓它結束。
- 故事線屬於家族，當事人死了也不會消失，會傳給繼承人。
- 階段會改變可用的事件、計畫和 AI 行為。例如處於血仇階段時，NPC 更可能發起「報復」計畫。
- 現在的「計畫」（追求、謀地、報復……）會改寫成一種短期故事線，共用同一套機制。

### 3.6 修正值（Modifier）：每個數字都能回答「為什麼」

所有算出來的數字（地租、收成、好感、死亡率、婚配機會）都由一疊修正值組成：

```
Modifier { 作用在哪個數值, 加或乘多少, 來源（特質 | 記憶 | 故事線 | 家族傳統 | 歷史事件 | 法律）, 到期日 }
```

UI 和除錯工具都能展開：「今年地租 156 便士＝基本 102 × 百年戰爭 1.15 × 領主的不滿 1.3」。

### 3.7 因果鏈（Causality）：追查任何一件事的來龍去脈

每筆 Deed 都記著起因（另一筆 Deed 或玩家指令），所以能形成一棵因果樹：

- **給玩家看**：家族編年史可以寫成「因為二十年前那場拒婚，兩家的孫子在婚禮上打了起來」。
- **給開發用**：任何怪結果都能往回追到源頭的指令或事件，配合指令重播，一定重現得出來。

## 4. 讓複雜度可控的工具

規則一多，彼此之間的交互作用會超出人腦能預測的範圍。所以這些工具和系統一起做，不是事後補：

| 工具 | 做什麼 |
|---|---|
| 資料檢查器 | 檢查所有 JSON：未知的鍵、指向不存在的特質、事件、Deed 類型；沒有任何東西會觸發的事件；沒有出口的故事線階段 |
| 千局統計 | 一次跑 1000 個種子，統計平均壽命、家族斷絕率、每個事件觸發幾次、每種故事線多久結束、財富分布。每改一次規則就跑，數字跑掉了馬上看得到 |
| 重播測試 | 用指令紀錄重播，結果必須完全相同（已經有了） |
| 因果查詢 | 指令列工具：「為什麼 X 死了」「X 和 Y 為什麼是世仇」，印出因果鏈 |
| 黃金劇情 | 幾個固定種子的編年史存成檔案，改動後比對差異，避免無意間改壞已經好玩的故事 |

## 5. 待決定

1. ~~玩家看得到多少~~ **已決定（2026-10-15）：只看自家人知道的事。** 秘密、傳聞要靠打聽；UI 與編年史都只顯示玩家家族成員知道的事。
2. **恩怨傳給下一代的強度。** 建議重大恩怨以約一半強度傳給繼承人，小事不傳。
3. ~~傳聞會不會失真~~ **已決定：會。** 秘密可以打聽，但打聽到的可能是錯的（見 3.3 的「信念」）。

## 6. 對照現有程式要改什麼

| 現有 | 改成 |
|---|---|
| `Person::flags` | 大部分改成 Deed 查詢；只留真正的「狀態」（例如身分） |
| `opinions_`（修正值清單） | 由記憶算出好感；修正值只留給特質、家族傳統 |
| `cooldowns_` | 查 Deed（「最近有沒有發生過」）或故事線階段 |
| 事件只靠定期抽選 | 定期抽選＋訊號觸發＋延遲觸發 |
| `ActivePlan` | 改成短期故事線 |
| 編年史直接寫字串 | 由 Deed 和因果鏈產生文字，可以回溯原因 |
| `World` 一個大類別 | 拆成模組：人口、經濟、社交（記憶、知情）、故事、事件，各自透過訊號溝通 |

1. 行為紀錄、記憶、好感由記憶算出（包括家族記憶）。把現有事件改寫成產生 Deed。 **（已完成 2026-10-15）**
2. 訊號與延遲佇列；事件可以掛訊號。 **（已完成 2026-10-15）**
3. 知情與傳聞；打聽、告發。**（已完成 2026-10-15；勒索、把柄、臨終招認也做了）**
4. 故事線；先做世仇、欠債，計畫改寫成故事線。**（世仇、欠債已完成 2026-10-15；計畫還沒改寫成故事線，但加了伏筆和事後的「為什麼」）**
5. 修正值層與因果查詢工具。**（部分完成：互動模式的「家裡知道什麼」會列出每份好感的來源，例如「（你做的）」「（上一代）」；正式的修正值層還沒做）**
