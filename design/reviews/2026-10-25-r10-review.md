## 高

### H1. 「家業怎麼分」算出來的繼承人，跟實際繼承的人不是同一個；用地安撫繼承人等於悄悄剝奪他的繼承權
- 位置：`simcore/src/kin.cpp:50-52`（`sonsOf` 把「自己當家」的兒子也算進來）、`kin.cpp:76`（`passPlan` 直接取 `sons[0]` 當繼承人）、`kin.cpp:883,886,928`（安撫時 `landed` 走 `setUpSon`）；對照 `simcore/src/life.cpp:523-530`（`heirOf` 的 `inHouse` 只認住在家裡、或在外但 awayFrom 是這一戶的人）。
- 問題：`sonsOf` 收了 `own`（已在別戶當家）的兒子，`passPlan` / `passWords` / `inheritText` 也就把他當成繼承人；可是 `heirOf` 不認已經分出去的兒子。兩邊只要不一致，就會出現：
  1. 繼承人「等太久」的不平（`kin.cpp:607-609`，對象是家主）會出現在季單「處理 X 的不平」裡。玩家選「安撫：分 3 畝地和 20 便士讓他自立門戶」，卡片沒說他從此不再是繼承人，可是 `setUpSon` 一跑，`heirOf` 就改成次子。NPC 照規則選 kind 0 也會這樣（`kin.cpp:914`）。法庭判同一戶的原告分地，走的也是 `setUpSon`（`kin.cpp:1061`），結果一樣。
  2. 換了繼承人以後，「身後的家業」那行（`inheritText`）還是寫「X（長子）繼承 N 畝和房子」。
  3. 家主死的時候，`applyPassing` 裡 `plan[0]` 是長子，被略過不處理（迴圈從 i=1 開始）；真正的繼承人（次子）因為 `s.who == heir` 也被略過。結果長子什麼也沒拿到，也沒記下任何 passGrudge。畫面上說的分法，跟實際發生的完全不一樣。
  4. 立了繼承人（named）的那個兒子如果搬出去（結婚、被安撫分家），`heirOf` 會默默退回長子：罰金照收了，畫面卻還寫著「立了繼承人：X 繼承」。
- 實測（seed 121，跑 3 年，探針程式）：
  ```
  before: sons[0]=奧斯伯特  heirOf=奧斯伯特  words: 奧斯伯特（長子）繼承 7 畝和房子；華特拿 30 便士…
  after setUpSon(奧斯伯特): heirOf=華特   words: 奧斯伯特（長子）繼承 4 畝和房子；華特拿 22 便士…
  ```
  三戶全都一樣。
- 違反的規則：玩家看不到的後果（繼承權不見了），而且畫面上的說法跟模擬自相矛盾。
- 建議：抽一個共用的 `planHeir(h, head)`，`passPlan` 和 `heirOf` 都用它。要嘛 `sonsOf` 的繼承人只取 `heirOf` 認的人，要嘛 `heirOf` 也認分出去的兒子（看設計要哪一種）。安撫卡如果對象是 `heirOf(ph, head)`，`landed` 選項要寫明「分出去就不再接家業，家業改歸 Y」，或乾脆不給這個選項。named 的繼承人不在家時，`inheritText` 也要寫出「X 不在家，會改由 Y 接」。

### M2. 同一戶裡偷錢，錢就從世界上消失了
- 位置：`kin.cpp:1130-1132`
  ```cpp
  th.money -= take, book(th, "被偷的錢", -take);
  Household& mine = households_[p.household];
  if (mine.id != th.id) mine.money += take, book(mine, "拿來的錢", take);
  ```
- 情境：家裡的不平多半是同住一個屋簷下（兄弟、媳婦、成年的兒子）。偷了之後，這一戶的錢減少，可是沒有任何人拿到。被撞破也一樣（`caught` 分支沒有把錢還回來）。帳本有記，所以 `unbookedMoney` 檢查會過，但全村的錢不守恆。對玩家來說，「【家醜】… 被撞個正著」之後，錢一樣沒了，也沒有交代去向。
- 建議：同一戶的話，被撞破就還回去（再記一筆「追回被偷的錢」）。沒被撞破，就記在偷錢的人身上（`Person` 加一個私房錢欄位，離家時帶走）。不然至少讓他離家或分家時，把這筆錢帶出去。

### M3. 「養老」交家沒有處理、也沒有清掉老家主定下的分法
- 位置：`kin.cpp:497-505`（`considerUpkeep` → `handOver`）；`simcore/src/life.cpp:1107-1149`（`handOver` 不碰 `passBy/passYounger/passHeir`）；`applyPassing` 只在 `onHeadDied` 裡呼叫。
- 情境 A：老家主定了「兒子們平分」或「弟弟們分一小塊地」，62 歲在莊園法庭交家給長子。他從此不是家主，死的時候不會進 `onHeadDied`，所以弟弟們永遠拿不到他定下的那一份，也不會記下 passGrudge。
- 情境 B：舊的 `passBy` 留在這一戶，就被當成新家主的安排，套到新家主自己的兒子身上。比方舊設定是 `named`、`passHeir` 等於新家主本人：新家主死時，`passPlan` 走 named 分支，弟弟們全部「什麼也分不到」。玩家這邊，`inheritText` 會顯示一個自己從沒選過的分法。
- 建議：立養老約的時候，照老家主的分法跑一次 `applyPassing(h, head, heir)`（弟弟們現在就拿到那一份，寡婦產則等老人死了再算），然後清掉 pass*。養老卡上要列出這些代價。

### M4. 寡婦產和分給兒子的份，畫面上說的跟實際給的不一樣
- 位置：`kin.cpp:78`（`passPlan` 先從整片地扣掉 `dowerOf`，再分給兒子）；`kin.cpp:379-380`（`applyPassing` 先把地分給兒子，再從剩下的地取三分之一當寡婦產）。

- 違反的規則：選擇前看到的代價必須是實際的代價。
- 建議：`applyPassing` 一開始就用 `dowerOf(h, dead, line)` 算出寡婦產（跟 `passPlan` 同一個基準），先保留下來再分。或者兩邊改成同一個順序。

### M5. 寡婦改嫁就帶走三分之一的地，可是決定她改嫁的那張卡沒提
- 位置：`kin.cpp:1451-1455`（`monthlyKin` 偵測到改嫁就呼叫 `dowerMoves`）；整個 `src/` 裡，「寡婦產」只出現在 kin.cpp 和 `life.cpp:988`。
- 情境：父親死了，玩家當家，親娘跟著住（`dowers_` 記成 from==in==這一戶）。之後有人來向母親說親或求親，卡片照舊只講對方家境和嫁妝。玩家答應以後，下個月 `dowerMoves` 就把約三分之一的地搬走。`inheritText` 只在父親生前提過一次「改嫁就帶走」，新家主的畫面上不會再出現。
- 建議：為家裡守寡、手上有 open dower 的人說親或求親時，在卡上加一行「她改嫁會帶走寡婦產 N 畝，她死了才回來」。`inheritText` 也可以列出目前還有效的寡婦產。
