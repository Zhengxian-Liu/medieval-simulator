# Medieval Simulator：架構設計

> 狀態：提案（2026-10-15）。配合 [GDD.md](GDD.md)。標 **待決定** 的地方需要 Zhengxian 拍板。

## 1. 總覽

```
┌──────────────────────────── Unreal（畫面、輸入、UI）────────────────────────────┐
│  USimSubsystem ── 推進時間、送指令、收事件                                      │
│  人物畫面：近景完整角色 / 遠景 Mass   鏡頭（等角 ↔ 第三人稱）   UI（事件卡、家譜）  │
└───────────────▲ 唯讀快照 + 事件佇列 ─────────────── 指令 ▼──────────────────────┘
┌──────────────────────────── SimCore（純 C++，不依賴 Unreal）────────────────────┐
│  時鐘（細步進 / 粗步進）  人物・家戶・家族  需求  活動與 utility AI  關係       │
│  事件系統  重點日子  歷史時間軸  經濟（物價、工資、財產）  繼承  存檔            │
└───────────────▲ 讀取 ─────────────────────────────────────────────────────────┘
          data/（JSON、CSV：事件、活動、特質、志向、物品、歷史時間軸）
```

原則：
- **SimCore 是唯一的真相。** Unreal 只讀它的狀態來畫，玩家的操作一律包成指令送進去。
- **內容是資料，不是程式。** 事件、活動、特質、志向、物品、歷史事件都放在 `data/` 的文字檔，Claude 可以直接寫、可以 diff。
- **可決定性。** 同樣的初始狀態、亂數種子、指令序列，一定跑出同樣的結果。存檔、重播、除錯、測試都靠這點。

## 2. SimCore 用什麼寫（已決定 2026-10-15）

**標準 C++20，不引用任何 Unreal 型別**，用 CMake 也能獨立編譯。

- 好處：雲端的 Claude 不能跑 Unreal，但可以編譯並測試 SimCore。寫事件、調數值、跑一百年的模擬測試，都可以在雲端完成，不必等你的 Mac。
- 代價：要多一層轉換（`std::string` ↔ `FString` 之類），而且不能用 Unreal 的反射和序列化。

Unreal 那邊用一個很薄的模組（`SimBridge`）包住 SimCore。

## 3. 資料模型

所有東西用整數 ID 互相參照（`PersonId`、`HouseholdId`、`DynastyId`、`PlaceId`、`ItemId`），不用指標，存檔和重播都比較單純。

| 實體 | 主要欄位 |
|---|---|
| Person | 姓名、性別、生日、父母、配偶、家戶、階級；特質（天生＋個性）；技能；五項需求；健康、名聲；目前活動與位置；志向（家主） |
| Household | 成員、家主、房子、存糧與物品、錢、田地、家業（鋪子、行會身分、頭銜） |
| Dynasty | 姓氏、歷代家主、家族傳統、家族名聲 |
| Item | 種類、品質、製作者、歷任擁有者（**傳家寶**就是有歷史的物品） |
| Place | 房屋、田、教堂、酒館、鐵匠鋪、磨坊、莊園；彼此的距離（地點圖） |
| Opinion | 人與人之間的好感，由多個帶衰減的修正值組成（Crusader Kings 的做法），以稀疏表存放 |

### 位置：模擬只管「在哪個地點」

SimCore 不處理座標和尋路，只知道「某人在鐵匠鋪」或「某人正從家走去教堂，幾點到」。
走路的路線、動畫、避開別人，都由 Unreal 的導航負責。移動時間由地點圖的距離算出來，兩邊對得上。

這樣快轉時不用算任何路徑，模擬一百年也很快。

## 4. 時間：兩種步進

| 模式 | 步進 | 什麼時候用 | 怎麼算 |
|---|---|---|---|
| 細步進 | 1 遊戲分鐘 | 重點日子、玩家拉近到某一天 | 每個人依 utility AI 選活動，需求逐分鐘變化，活動逐步完成 |
| 粗步進 | 1 遊戲天 | 平常的快轉 | 每人依作息範本與季節計畫，一次算完一天：需求淨變化、產出、技能成長、社交機會 |

**一致性**：兩種模式讀同一份活動定義（每小時需求變化、產出、技能經驗），粗步進等於把一天的作息直接積分。測試會比較同一段時間用細步進和粗步進跑出的結果，誤差要在範圍內。

村莊約 100 人，重點日子全村都用細步進，負擔很小。之後擴展到市鎮、地區時，遠方的人改成每月更新的粗略模擬。

## 5. 村民決策（utility AI）

- **活動定義**（`data/activities.json`）：需要的地點、工具、技能；時長；對需求、健康、技能、物品、關係的影響。
- **作息範本**：依職業和季節分時段（例如春天的農民：日出下田、中午吃飯、傍晚回家）。時段內的具體活動由打分決定。
- **打分**＝需求急迫程度 × 活動滿足量 ＋ 個性加權 ＋ 指派加權 ＋ 關係（想和誰在一起）。
- **玩家指派家人**：大幅提高某項活動的分數。如果家人的個性、心情、或對家主的好感跟指派衝突，他會拖延、偷懶，或觸發「頂嘴」「離家」之類的事件。
- **家主**：玩家直接下指令時，跳過打分。玩家沒下指令時，同樣由 AI 自動生活。

## 6. 事件系統

> 後果、記憶、連鎖反應的完整設計見 [consequences.md](consequences.md)。

事件寫在 `data/events/*.json`，格式類似 Crusader Kings：

```json
{
  "id": "smith_apprentice_offer",
  "scope": "person",
  "trigger": { "pulse": "monthly", "weight": 10 },
  "conditions": { "all": [ { "age": [10, 14] }, { "not": { "has_occupation": true } } ] },
  "text": "events.smith_apprentice_offer.desc",
  "options": [
    { "text": "...accept", "effects": [ { "set_occupation": "apprentice_smith" }, { "opinion": { "target": "event.smith", "value": 15 } } ] },
    { "text": "...refuse", "effects": [ { "trait_chance": { "trait": "stubborn", "chance": 20 } } ] }
  ],
  "ai_choice": [ { "option": 0, "weight": "skill.smithing * 2 + 10" } ]
}
```

- **觸發方式**：定期脈衝（每天、每月、每季，帶權重抽選），或掛在某個動作上（結婚、死亡、活動完成時）。
- **條件與效果**：先用 JSON 條件樹，夠用就不另做腳本語言。
- **NPC 也會遇到事件**，由 `ai_choice` 自動選，所以村裡的故事不只發生在玩家身上。
- **連鎖事件**：選項可以排程後續事件（「三個月後」），或在人身上留旗標。
- **在地化**：文字用鍵值，放在語言檔，中英文分開。

## 7. 重點日子

重點日子（市集日、節慶、婚禮、喪禮、收成日、莊園法庭日）由 `data/keydays/*.json` 定義：日期規則、會到場的人、可做的事、當天的小目標和結算。
當天切成細步進，鏡頭自動拉近到村子。

## 8. 歷史時間軸與難度

- `data/history.json`：帶日期的大事，觸發後修改世界參數（物價、工資、稅、死亡率、法律），並發出全村事件。
- 開局選年份時，從時間軸重建當年的世界參數。
- **殘酷程度**是一組參數（死亡率倍率、是否保底留一個繼承人）。

## 9. 指令、存檔、重播

- 玩家的每個操作都是一個 `Command { tick, type, payload }`。SimCore 只透過指令改變狀態。
- 亂數：每個子系統一條獨立的 PCG 亂數流，從主種子衍生。這樣改了一個系統，不會讓其他系統的亂數全部錯位。
- 存檔：最近的完整快照（版本化二進位）加上之後的指令紀錄。
- 除錯：任何錯誤都能從快照加指令重現，雲端也能重播。

## 10. Unreal 這一層

| 元件 | 職責 |
|---|---|
| `USimSubsystem` | 擁有 SimCore 的世界；依遊戲速度推進細或粗步進；把指令送進去；把事件佇列轉成 Unreal 事件 |
| 人物畫面 | 用 PersonId 對應到角色。鏡頭近時用完整角色（MetaHuman、可換衣服），遠時用 Mass 大量繪製 |
| 家居 | 傢俱、擺飾是 SimCore 裡的 Item，擺放位置存在 Household 裡；Unreal 只負責畫和擺放 UI |
| 鏡頭 | 縮放值 0–1 連續控制俯角、距離、FOV、景深（見 unreal-plan.md） |
| UI | 事件卡、家譜、季節計畫、人物面板 |

```

  include/ src/ tests/
data/               事件、活動、特質、志向、物品、歷史時間軸、語言檔
Source/SimBridge/   Unreal 薄包裝

tools/              資料檢查、事件預覽、「跑一百年」的編年史產生器
```

## 12. 建議的第一步（不需要 Unreal）

在 Unreal 還沒好之前，先在雲端做 **SimCore 文字版**：
- 一個農民家戶加上約 30 個村民；五項需求；10 種活動；20 個事件。
- 出生、成長、結婚、死亡、繼承；個性與特質遺傳。
- 指令列工具一次跑 100 年，輸出一份「家族編年史」文字檔。你讀起來覺得有故事，系統就方向正確。

這一步可以驗證傳承玩法好不好玩，也和畫面那條線平行，互不卡住。
