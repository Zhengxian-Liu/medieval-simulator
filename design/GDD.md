# Medieval Simulator：遊戲設計文件

> 狀態：討論中（2026-10-15 起）。標 **待決定** 的地方需要 Zhengxian 拍板。
> 取代舊版 `medieval-simulator/docs/GDD.md`（Godot 原型時期，偏村莊經營）。

## 一句話

扮演一個中世紀人，過完他寫實的一生：工作、交朋友、成家、面對人生大事。他死後由繼承人接手，目標是讓家族一代一代延續、壯大。

## 三個玩法層次（提案）

| 時間尺度 | 玩家在做什麼 | 參考 |
|---|---|---|
| 一天 | 安排家人的作息：工作、吃飯、睡覺、社交；照顧需求 | 模擬市民 |
| 一年 | 季節、收成、節慶、稅；事件卡片與選擇；家裡的衣著、傢俱 | Crusader Kings 事件 |
| 一生到數代 | 婚配、生子、教育、繼承、家族聲望、長遠目標 | Crusader Kings 傳承 |

## 時間節奏

三條規則：
1. **細節用來做選擇，不是用來等待。** 逐分鐘玩的日子都要有目的（市集日：賣貨、議價、八卦、遇見對象；婚禮：座位、親戚衝突）。
2. **平常日子交給計畫。** 每季開頭設定重心（種植、學徒、追求對象、存錢修屋），然後快轉；有意思的事自動暫停並跳出事件卡。
3. **任何一天都能自己拉近。** 想看晚餐、重新擺傢俱可以隨時停下來，但不強迫。

暫定節奏（待原型驗證）：一年 15–25 分鐘，含 4–6 個重點日子，每個 3–5 分鐘；一代家長約 6–10 小時。

架構影響：SimCore 要有兩種步進。**細步進**（1 遊戲分鐘，重點日子與玩家拉近時）和**粗步進**（以天為單位，用統計結果推算工作產出、需求、關係變化）。兩種步進的結果要大致一致，否則玩家會發現拉近和快轉的結果不同。

## 傳承：上一代如何影響下一代

| 傳下去的東西 | 例子 | 對下一代的影響 |
|---|---|---|
| 家業 | 田地、鐵匠鋪、工具、行會身分、莊園頭銜 | 父承子業最容易；換行要從學徒做起，或花錢、靠人脈 |
| 教育 | 小時候誰教他、跟誰學藝、有沒有讀書（神父教識字） | 決定起始技能，也影響特質和可選的志向 |
| 特質 | 天生（強壯、體弱、聰明、俊美，部分遺傳）＋ 個性（勇敢、貪婪、虔誠、易怒），個性由父母和童年事件塑造 | 影響事件選項、家人是否服從指派、人際關係 |
| 名聲與人情 | 家族名聲、欠誰人情、和誰家有世仇 | 婚配對象、村民態度、會觸發的事件 |
| 財產與傳家寶 | 房子、傢俱、擺飾、衣服、傳家寶 | 和模擬市民式的家居連結：父親做的桌子、祖母的嫁妝箱可以一直傳下去 |
| 家族傳統 | 每代完成志向後可留下一條家訓或傳統（例如「鐵匠世家」「虔誠之家」） | 永久加成，累積成家族的身分 |

**童年是傳承的關鍵時期**：孩子成長時，玩家透過指派（跟誰學、做什麼家務、送去當學徒或教會）和童年事件塑造他的個性與技能。這是讓玩家在家主還活著時，就開始為下一代做準備。

**志向**：家主成年或繼位時，從一組候選志向中選一個（例如「讓兒子進行會」「蓋石屋」「與莊園家族聯姻」「還清債務」「成為村裡最好的鐵匠」）。候選清單由個性、家業、教育、名聲決定。

## 中世紀的規範（提案，2026-10-15）

目標：讓玩家在遊戲裡遇到「現代人覺得匪夷所思、當時理所當然」的事，而且這些事要變成**系統和選擇**，不是只出現在文字裡。以下是 14 世紀英格蘭的真實制度，都可以做成機制。

| 主題 | 當時的常態 | 遊戲裡怎麼體現 |
|---|---|---|
| 婚姻是家族生意 | 父母談親事，看的是嫁妝和土地；感情是其次 | 婚事變成兩家談判：嫁妝、聘地、對方家聲望；兒女可能反抗 |
| 寡婦快速再嫁 | 有地的寡婦幾個月內再嫁很常見，因為田需要男人種 | 有地寡婦成為搶手對象；守寡會讓田荒 |
| 農奴身分 | 農奴不能自由離開莊園；女兒出嫁要繳「婚姻稅」（merchet） | 身分分自由民與農奴；遷居、婚嫁、進教會都要領主許可或付錢；可以花錢或靠逃跑換自由 |
| 死後的稅 | 農奴死後，領主取走家裡最好的一頭牲口（heriot），教會再拿第二好的 | 繼承時自動扣財產，讓「死亡」在經濟上也痛 |
| 未婚懷孕的罰款 | 莊園法庭會罰未婚有性行為的女子（leyrwite） | 醜聞事件、罰款、名譽損失；私生子沒有繼承權 |
| 教會曆 | 四旬期不吃肉、不辦婚禮；近親（四等親內）不能結婚 | 曆法限制婚禮與飲食；表親想結婚要花錢求教會特許 |
| 孩子是勞動力 | 七八歲就幹活，十二三歲常送去別家當僕人或學徒 | 「送孩子出去當僕人」是正常選項，換錢、換人脈，也換來孩子的疏離 |
| 衣著按階級 | 1363 年《節約法令》規定各階級能穿什麼布料、顏色 | 模擬市民式的衣著系統受法律限制；穿得超過身分會被罰、被嘲笑 |
| 名譽靠法庭 | 罵人、造謠可以告上莊園法庭；村民會用敲鍋遊街羞辱不合宜的婚事 | 名譽是可被攻擊的資源；誹謗、鬧婚事件 |
| 疾病的解釋 | 瘴氣、體液失衡、上帝的懲罰；放血、朝聖、鞭笞派遊行 | 治療選項大多沒用甚至有害，但玩家看不到真實機率，只能相信當時的說法 |
| 家長的權力 | 丈夫依法可「管教」妻子，師傅可打學徒 | 透過事件和關係呈現，讓家人的服從與怨恨有來源（呈現方式要謹慎） |

**SimCore 已實作（2026-10-15）**：自由民／農奴身分（隨父親血緣傳承）、婚姻稅（嫁出莊園加倍）、死後稅與喪葬捐、農奴的勞役（收成打折、現金地租較低）、贖身計畫與「替全家贖身」志向、什一稅、送孩子去幫傭（好主人／壞主人會留下恩怨）、黑死病後逃到鎮上、四旬期、聖誕節領主宴、祈禱日巡界。還沒做：未婚懷孕罰款、近親婚禁令與特許、節約法令、敲鍋遊街、疾病療法、家長管教。

## 核心循環（提案）

1. 生活：主角和家人在村裡自主過日子，玩家調整優先順序、偶爾直接操作。
2. 事件：日常會冒出事件（求婚、爭執、疾病、領主徵稅、豐收、火災），玩家做選擇。
3. 後果：選擇改變關係、名聲、財富、健康、技能，也可能埋下之後的事件。
4. 累積：錢和名聲花在房子、傢俱、衣著、子女教育、嫁妝、土地上。
5. 傳承：主角死亡 → 選繼承人（或依繼承法）→ 繼承財產、名聲、宿怨 → 繼續。

## 架構（摘要，細節見 [architecture.md](architecture.md)）

- **SimCore**：純 C++ 模組，不依賴 UObject / Actor。固定步進（暫定 1 遊戲分鐘），可決定性重播，可在 Automation Test 裡快速模擬數十年。
- **指令**：玩家操作包成 Command 送進 SimCore，存檔＝初始狀態＋種子＋指令紀錄（另存快照加速讀檔）。
- **村民決策**：utility AI，依需求、個性、關係、時間對可做的事打分。
- **事件系統**：事件定義放資料檔（JSON/CSV → DataTable），包含觸發條件、選項、後果，Claude 可直接編寫和 diff。
- **兩種精度**：玩家家族與附近的人完整模擬；遠方的人粗略模擬（每天或每月更新一次）。
- **畫面層**：Unreal 讀 SimCore 快照來畫，不修改狀態。遠景人物用 Mass，近景換完整角色。
